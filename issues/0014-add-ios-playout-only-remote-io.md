# 入力を使用しない受信専用 RemoteIO を追加する

- Branch: feature/m150.7871
- Polished: {YYYY-MM-DD}

## 目的

音声を受信して stereo 再生するだけの利用で、マイク入力やマイク権限を必要としないネイティブ音声経路を提供する。

## 現状

調査対象は `m150.7871.3.2` と `ios_stereo_audio_output.patch` である。

- `RemoteIOAudioUnit` は入力側の `kAudioOutputUnitProperty_EnableIO` を有効にし、入力コールバックも設定する。
- 再生を stereo にした場合でも入力は mono であり、受信専用であることを指定するプロファイルがない。
- Sora iOS SDK の PR #381 はネイティブ stereo を `recvonly` で利用する場合も `playAndRecord` を要求する。
- 録音データの転送を止める処理だけでは、AudioUnit の入力自体やマイク権限への依存を取り除けない。

## 設計方針

- AudioUnit の初期化前に、入力を必要とする利用と再生だけの利用を区別する設定を設ける。現在の利用方法の既定動作は維持する。
- 再生だけの場合は入力 I/O と入力コールバックを使用しない。入力パラメーター、バッファ、録音開始処理もこの設定に従わせる。
- AudioSession の category と mode、および `canPlayOrRecord` などの開始条件を確認し、マイク権限に依存せず再生を開始できるようにする。
- 初期化、再初期化、割り込み、経路変更で入力が意図せず再度有効にならないようにする。
- 初期化済みの AudioUnit をその場で送受信用へ切り替える仕様は追加しない。入力が必要になった場合の再生成条件を明文化する。
- 本 issue の設定と既存 issue 0010 の API 統合設計を整合させる。stereo 録音を扱う既存 issue 0006 は対象外とする。

## テスト方針

実機で、マイク権限が未決定または拒否された状態から受信専用の再生を開始する。
権限ダイアログ、入力の使用状態、実際の左右の再生、再接続、経路変更を確認する。
入力が必要な送受信の動作も確認し、モックやスタブは使用しない。

## 完了条件

- 受信専用プロファイルで入力 I/O を使用せず、マイク権限を要求せずに再生できる。
- マイク権限が拒否されていても受信専用の再生を開始できる。
- 再初期化や経路変更後も入力を使用しない状態が維持される。
- 従来の入力を使用する mono / stereo 出力の送受信が動作する。
- 利用側が必要なプロファイルを選択でき、設定時期と再生成条件が説明されている。
- 実機の検証条件と結果が記録されている。
